# 02 创新点凝练

凝练，是把做过的工作归纳成几个创新点，每一点都能让编辑一眼看出：针对什么问题、提出了什么、怎么构建的、得到了什么。

级别的写法见《01 包装》开头。

---

## 一、六位句式与五个问题

**INNOV-01（必守）创新点的六位句式。**

> 针对……问题，提出……方法。该方法将……建模为……分布或随机过程，并以……作为……参数，在……约束下推导得到……，该结果在……条件下达到……。

一句里有六个位置，按顺序填：
1. 问题：现有方法怎么做，没有考虑什么，因此出了什么毛病；
2. 名字：提出的方法或模型叫什么；
3. 建模：把哪个对象建模为哪种分布或随机过程；
4. 参数：分布的参数由什么给出；
5. 推导：在什么约束下推出什么结果；
6. 性质：这个结果在什么条件下达到什么，例如最优、上界、下界或闭式表达。性质放在句末。

- 例（虚构）：针对假定工作温度恒定的剩余寿命预测方法 [12] 无法给出温度分段恒定时剩余寿命分布的问题，提出分段温度下的剩余寿命预测方法。该方法将温度分段恒定时容量的衰减过程建模为分段漂移的维纳过程，并以各温度段由阿伦尼乌斯关系给出的漂移系数作为参数，在各段漂移系数为正的约束下推导得到剩余寿命的分布；该结果在温度恒定时退化为逆高斯分布，且在活化能为正、扩散系数不随温度变化的条件下，任一温度段的温度升高而其余各段不变时，平均剩余寿命单调缩短。
- 例中的维纳过程退化模型、阿伦尼乌斯关系、维纳过程首达时间服从逆高斯分布，以及恒定温度下平均剩余寿命随温度升高而缩短，都是已有结果，正文中注明出处；属于我们的是温度分段恒定时的建模、剩余寿命分布的推导，以及分段情形下平均剩余寿命单调性的证明（PACK-14）。
- （建议）并非每个创新点都有“分布”。没有时，第 3、4 位写成“将……形式化为……，以……作为……”，其余位置不变。

**INNOV-02（必守）每个创新点回答五个问题。**
1. 这是第几点，叫什么；
2. 针对什么问题：已有做法的不足是什么；
3. 怎么构建的：模型的形式，参数从哪里来，输出是什么；
4. 用了谁的理论，为什么用；
5. 得到什么，带上成立的条件，放在最后说。

## 二、不接受的写法

**INNOV-03（必守）不把功能或结论当创新点。** 创新点写的是怎么构建的；方法带来的好处是结论，放在句末，作为带条件的性质。

**INNOV-04（必守）不只给名字，要落到技术细节。** 名字之后写出“该模型将……建模为……，以……作为参数”。只写“将寿命预测建模为一个回归问题”不够：要写到“将容量的衰减过程建模为漂移系数由温度决定的维纳过程”，剩余寿命的分布由这个模型推出。

**INNOV-05（必守）起名。**
- 每个创新点、每个新对象都要有名字。已有的分布用文献中的名字（PACK-10）。我们推导出的分布，按 LIT-06 检索、确未见于文献的，才另起名；起名不等于称新，正文写“推导出……分布”，不写“提出一种新的分布”（PACK-14）。
- 按作用起名，不按构件起名。例：某组件的作用是在温度变化时校正预测，就叫“……温度校正”，不叫“双分支网络”。
- 我们新定义、文献中没有的量（由公式给出），要起名，并写出其含义。
- 选用文献中已有的分布本身不构成创新点（引用原文）；创新点写针对该问题的建模方式（INNOV-03、INNOV-04）以及由此推出的带条件的性质。
- 名字可以再换；名字要让人看得出为什么这么叫，但不用括号去解释（见《06 中文书面语》CN-02）。

**INNOV-06（必守）标题和小标题说一个关系或一个对象，不说一项操作；正文也不写成操作清单。** 例：`EX-INNOV-06`。只改标题不够，正文要写成由命题推出的性质（见 SCI-03）。

## 三、创新点从哪里来

**INNOV-07（必守）在已有工作上改进。** 创新点可以来自对已有方法的改进：被改进的方法给出引用；创新点是我们的改动及其效果，不是被改进的方法本身。
- （建议）各个改动最好回答同一个成因，否则读起来像拼凑。每个创新点先填一行：已有方法 → 在我们的数据上怎么失败（用实验，不用论证）→ 我们的改动 → 去掉改动的消融。

**INNOV-08（必守）先深入分析问题的成因，再从成因推出创新点。** 成因可以在综述里找；修法可以取自别人的方法，引用原文。原样使用的修法不算我们的创新：创新点写我们的诊断，以及我们对修法所做的改动。哪个成因在本数据上成立，由我们自己的诊断实验决定。

**INNOV-09（建议）创新点的数目由真实的贡献决定。** 某个设计效果不好时，先诊断原因，再决定修改或舍弃，并如实报告。现成方法简单套用不算创新；诊断出的失败，加上我们针对该失败提出或改造的修法，才是。

## 四、主线与次序

**INNOV-10（必守）全文扣住一条主线：一个科学问题。** 每个创新点都扣在这条主线上；编辑读完要能看出作者解决了该问题的哪一部分。

**INNOV-11（必守）挑战、缺陷、方法一一对应。** 引言里 N 个挑战、现有方法的 N 个缺陷、方法的 N 个组件、方法图的 N 个分图，次序处处一致。摘要的创新点次序与之相同。每个缺陷须由所引方法的原文支持；对不上时调整挑战或组件的划分，不为凑齐对应而把缺陷归给现有方法（ABS-07、LIT-04）。细则见《04 引言与结论》。

**INNOV-12（必守）问题先行；问题从句先写前提，再写后果。**
- 创新点和它下面的子点一般以“针对……问题”开头。
- 先写前提，再写后果。例：“实际工况中温度按时段变化……假定温度恒定的模型因而无法给出温度分段恒定时的剩余寿命分布”。
- 例外：某个创新点的问题从句不好懂，或字数很紧时，可以去掉问题从句，直接写“首先，建立……”（ABS-13）。

**INNOV-13（必守）各创新点的句式要有变化。** 不都写“提出”。例：“建立……模型”“推导……分布”“设计……策略”；英文 build / derive / design。

**INNOV-14（必守）核心创新点写足，次要的写精。** 核心的一点要详细叙述，可以有子点；子点也按 INNOV-01 的骨架写。每个子点都是我们实际做的工作（推导的结果、证明的性质、新的构造等）；不属于我们的内容不列为子点（PACK-02）。例：`EX-INNOV-14`。

**INNOV-15（建议）言简意赅，短小精悍。**

## 五、凝练的步骤（动笔前做完）

1. 写下主线：一个科学问题（INNOV-10）。
2. 列出挑战—缺陷—组件对应表（INNOV-11）。
3. 每个组件填一行改进表（INNOV-07），并核对已有方法的描述与原文一致（《08 文献检索》LIT-04）。
4. 每个组件按 INNOV-01 的六个位置各写一句话的要点，缺哪个位置就补哪个。
5. 列出每个组件中真正属于我们的部分（PACK-02），子点逐条写成我们实际做的工作；其余部分注明出处。
6. 起名（INNOV-05），检查各创新点的句式是否有变化（INNOV-13）。
7. 先写长版，再压成摘要和贡献列表（《03 摘要》ABS-01）。

## 六、改完自问

- **INNOV-Q1（自问）** 去掉名字，这句话还能说出“怎么构建的”吗？
- **INNOV-Q2（自问）** 句末是性质加条件，还是只有功能？
- **INNOV-Q3（自问）** 每个创新点是否都扣在主线上？
- **INNOV-Q4（自问）** 各创新点的动词和句式是否一样？
- **INNOV-Q5（自问）** 每个子点是不是我们实际做的？借来的部分是否注明了出处？
